# Task 12 — i18n: `tasks.json` + strings de push notification

Fecha o épico ([visão geral](00-visao-geral.md)). Depende das tasks 07, 08, 09, 10 (precisa
saber todas as chaves usadas pelos componentes) — fazer por último, ou junto com cada task de
UI se preferir ir incrementando (mais fácil revisar tudo de uma vez no fim, por isso está
numerada como a última).

## Objetivo

Consolidar as chaves de i18n introduzidas pela feature. **Tasks é um domínio novo**, fora da
exceção Kanban/automation/macros do `AGENTS.md`/CLAUDE.md — regra geral: só editar `en`. Não
sincronizar `pt_BR` a menos que o usuário peça explicitamente (avisar antes de assumir).

## 1. Novo arquivo `app/javascript/dashboard/i18n/locale/en/tasks.json`

Namespace `TASKS`, mesmo estilo de `SCREAMING_SNAKE_CASE` com sub-namespace `API` para
mensagens de sucesso/erro (padrão `KANBAN.ITEM.API.CREATE_SUCCESS` em `kanban.json`):

```json
{
  "TASKS": {
    "EMPTY_STATE": "No tasks yet",
    "CREATE": "Add task",
    "TITLE_PLACEHOLDER": "Task title",
    "DUE_DATE_LABEL": "Due date",
    "ASSIGNEE_LABEL": "Assignee",
    "OVERDUE_BADGE": "Overdue",
    "PAST_WINDOW_WARNING": "This due date is more than 3 days in the past — no reminder will be sent.",
    "COMPLETE_ACTION": "Mark as done",
    "DELETE_ACTION": "Delete",
    "API": {
      "CREATE_SUCCESS": "Task created",
      "CREATE_ERROR": "Could not create task",
      "UPDATE_SUCCESS": "Task updated",
      "UPDATE_ERROR": "Could not update task",
      "DELETE_SUCCESS": "Task deleted",
      "DELETE_ERROR": "Could not delete task",
      "COMPLETE_SUCCESS": "Task marked as done",
      "COMPLETE_ERROR": "Could not update task"
    }
  }
}
```

Ajustar as chaves exatas conforme o que os componentes das tasks 07-10 efetivamente usam (essa
lista é um ponto de partida, não uma lista fechada — grep por `t('TASKS.` nos componentes
implementados antes de finalizar este arquivo, para não deixar chave usada sem tradução nem
chave sobrando sem uso).

Confirmar que o arquivo é carregado automaticamente (o projeto tem 58 pastas de locale, cada
uma com múltiplos arquivos JSON por domínio — conferir como `i18n/index.js`
ou equivalente agrega os arquivos de um locale, mas pelo padrão observado em outros domínios
não deve precisar de registro manual, só criar o arquivo no lugar certo).

## 2. Chaves específicas fora de `tasks.json` (cada uma na regra do seu próprio domínio)

- `KANBAN.ITEM.TASKS.TITLE` (task 08) → **`en` + `pt_BR`**, é domínio Kanban.
- `CONVERSATION_SIDEBAR.ACCORDION.TASKS` (task 09) → checar domínio do arquivo antes de decidir
  (ver nota na própria task 09).
- `CONTACTS_LAYOUT.SIDEBAR.TABS.TASKS` (task 10) → regra geral, só `en`, a menos que já exista
  precedente de sync nesse arquivo específico.
- `PROFILE_SETTINGS.FORM.NOTIFICATIONS.TYPES.TASK_DUE` (task 11) → regra geral, só `en`.

## 3. Backend — strings de push notification

`config/locales/en.yml` — já cobertas na task 03 (`notifications.notification_title.task_due`,
`notifications.task_due_body`). Esta task só confirma que essas chaves existem e que
`push_message_title`/`push_message_body` (task 03) não retornam string vazia para `task_due`
antes de fechar o épico.

## Critério de pronto

- `pnpm eslint` sem warnings de `vue/no-bare-strings-in-template` em nenhum componente novo de
  Tasks (garante que nenhuma string ficou hardcoded fora do i18n).
- Todas as telas das tasks 07-11 renderizam texto (não chave crua tipo `TASKS.EMPTY_STATE`) em
  `pnpm dev`.
- Notificação push de tarefa vencida (testável via task 04) mostra título/corpo legível, não
  vazio.
